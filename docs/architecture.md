# MONBLAN アーキテクチャ

## プロセス構成

MONBLANは、次の3層で構成します。

| 層                     | 主な責務                                                           |
| ---------------------- | ------------------------------------------------------------------ |
| Electronメインプロセス | ウィンドウ、ファイル保存、ローカル動画配信、Python APIの起動・停止 |
| React Renderer         | 動画表示、タイムライン編集、EAF入出力、AI処理の操作UI              |
| FastAPI                | 動画情報取得、AlphaPose・MotionBERT・動作検出・類似検索の実行      |

RendererではNode.js APIを直接利用しません。必要な操作だけを`preload.ts`の`contextBridge`から公開します。

## ローカル動画

動画選択直後はブラウザのBlob URLを使用します。EAFや旧プロジェクトJSONから絶対パスを復元する場合は、Electronメインプロセスへパスを登録し、`monblan-media://`プロトコルの一時URLへ変換します。

この構成により、Rendererの`webSecurity`を有効にしたままローカル動画を再生できます。専用プロトコルが受け付けるのは、存在する動画ファイルと許可済み拡張子だけです。

## Python API

Electronは`127.0.0.1:8000`でMONBLAN APIを確認し、未起動の場合だけ管理対象プロセスとして起動します。`/health/`のサービス名とプロトコル版が一致しない場合は、別サービスとのポート競合として扱います。

アプリ終了時に停止するのは、Electronが起動したAPIプロセスだけです。利用者が別途起動した互換APIは再利用し、終了対象にはしません。

## AI処理と外部資源

AlphaPose、MotionBERT、モデル重み、Python仮想環境は配布物へ含めません。初回セットアップ後はユーザーデータ領域のAI環境を利用します。

重い処理はジョブ単位で一時ディレクトリへ出力し、失敗時は調査用に保持します。AlphaPose、MotionBERT、類似検索の再利用可能な結果は、動画のパス・更新状態・分析条件などから生成したキーでキャッシュします。

## 保存形式

利用者向けの主要保存形式はEAFです。既存EAFを読み込んだ場合は、MONBLANが直接編集しない参照注釈、未知要素、メタデータを元XMLから保持して再出力します。

旧MONBLANプロジェクトJSONは読み込み互換のみ提供し、読み込み後の保存先はEAFになります。

## テスト方針

- Renderer: EAF往復、未知要素・参照注釈の保持、共通通知キュー
- Python: 進捗状態のコピー、更新、削除、コールバック
- CI: Lint、TypeScript型検査、Rendererテスト、Pythonテスト、本番ビルド
- 手動確認: 動画再生、EAF読込後の動画復元、AI環境セットアップ、インストーラーを使ったクリーンPC検証
